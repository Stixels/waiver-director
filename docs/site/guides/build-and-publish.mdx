## Edit the draft

The waiver builder has three parts:

- **Title**: shown at the top of the public waiver page. Rename it from the page header.
- **Waiver copy**: the terms signers agree to, written in a rich-text editor with headings, lists, links, and alignment.
- **Custom fields**: questions signers answer before signing.

Every waiver also collects the signer's details and a drawn signature, and lets an adult add **covered minors** who are signing under the same waiver.

You can also choose a light or dark theme for the public waiver page.

### Custom field types

| Type     | Use it for                                                   |
| -------- | ------------------------------------------------------------ |
| Text     | Free-form answers, such as an emergency contact              |
| Checkbox | Agreements or yes/no questions                               |
| Dropdown | One choice from a list, such as "How did you hear about us?" |
| Date     | Dates, such as a date of a previous visit                    |

Any field can be marked required. Dropdown answers feed into [analytics](/guides/analytics).

## Publish

Publishing saves the current draft as a new **published waiver version** and makes it the version customers sign. Edits you make after publishing stay in the draft until you publish again.

<Warning>
	Publishing requires a Pro plan or trial. On the Free plan you can build the waiver and preview the
	public signing page, but customers cannot submit it.
</Warning>

## Version history

Open the version history from the waiver page to see every version you have published. Signed submissions always point to the exact version the signer accepted, so older signatures keep their original wording after you republish.

## Multiple waivers

Use the waiver menu next to **Publish** to switch between waivers. Each waiver has its own public link, QR code, drafts, and version history.

Owners can:

- **Create a waiver**: choose **New waiver** in the waiver menu and give it a title.
- **Change the default waiver**: open the waiver, then choose **Make default waiver** from the **⋯** menu. The default waiver is the one every activity uses unless you set an activity-specific requirement.
- **Archive a waiver**: choose **Archive waiver** from the **⋯** menu. Its public link stops working and it is removed from activity requirements. Signed submissions and version history are kept. The default waiver can't be archived; make another waiver the default first.

A workspace can have up to 25 active waivers.

### Activity requirements

Choose **Activity requirements** in the waiver menu to pick which waivers each activity needs.

<Frame caption="Sample data from a fictional workspace.">
	<img
		src="/images/app/activity-requirements.png"
		alt="Activity requirements panel listing activities with the waivers each one requires"
	/>
</Frame> Activities appear once bookings sync from your booking provider, or you can add one by the name it has on bookings.

An activity-specific requirement **replaces** the default waiver for that activity; it doesn't add to it. To require the default waiver as well, select it too. Guests who open a booking link see every waiver their activity needs and are taken to the next one after they sign.

<Note>
	The waiver gap on a booking counts signatures on the first waiver the activity requires. Coverage
	for each additional waiver isn't tracked separately yet.
</Note>
